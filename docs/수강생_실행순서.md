# 수강생 실행 순서

모든 명령은 `student/` 폴더에서 실행합니다.

---

## A. 강의 전날 — 환경 만들기  (약 40분, 대부분 대기)

### A-1. 패키지 설치

```
python -m pip install -r requirements.txt
```

`boto3` · `requests` · `python-dotenv` 세 개만 설치됩니다.
AWS CLI 는 필요 없습니다.

### A-2. 설정 파일 만들기

```
copy .env.example .env          (Windows)
cp .env.example .env            (macOS / Linux)
```

`.env` 를 열어 **위쪽 다섯 줄**을 채웁니다.

```
STUDENT_NAME=steve                    소문자/숫자/하이픈 2~20자
AWS_ACCESS_KEY_ID=<받은 키>
AWS_SECRET_ACCESS_KEY=<받은 시크릿>
AWS_DEFAULT_REGION=ap-northeast-2
ALERT_EMAIL=본인메일@회사.com          ← 꼭 채우세요
```

아래쪽 `AUTO GENERATED` 구간은 건드리지 않습니다. 배포하면 자동으로 채워집니다.

### A-3. 인프라 배포  ★ 25~35분

```
python deploy_lab.py
```

**일어나는 일**

1. CloudFormation 스택 생성 — VPC + **EKS Auto Mode 클러스터** (약 12분)
2. CodeBuild 부트스트랩 — **ArgoCD** 와 **Gitea** 를 클러스터에 설치 (약 8분)
3. Git 저장소 생성 + 앱 매니페스트 커밋
4. **ArgoCD Application 생성** → 앱이 실제로 배포되고 Healthy 확인
5. `.env` 아래쪽에 클러스터·Git 주소 자동 기록

대부분이 대기 시간입니다. 켜두고 다른 일 하셔도 됩니다.

### A-4. 메일 구독 확인  ★ 놓치기 쉬움

배포 후 **AWS Notifications** 에서 확인 메일이 옵니다.

```
제목: AWS Notification - Subscription Confirmation
```

**본문의 `Confirm subscription` 링크를 눌러야** 에이전트 리포트가 메일로 옵니다.
스팸함도 확인하세요.

메일이 안 왔거나 놓쳤다면:

```
python alerts.py 본인메일@회사.com     구독 추가
python alerts.py                      구독 상태 확인
python alerts.py --test               테스트 메일 발송
```

### A-5. 점검

```
python check_env.py
```

**10개 항목이 전부 ✅ 여야 합니다.**
❌ 가 하나라도 있으면 화면을 캡처해 강사에게 보내주세요.

## B. 강의 당일 — 한 바퀴 돌리기

### B-1. 출발선 확인

```
python status.py
```

**보이는 것**

```
ArgoCD  kdt-dev-api
  sync   Synced      health Healthy      자동동기화 켜짐
Pods
  kdt-dev-api-xxxxx   Running   ready=True   restarts=0
  kdt-dev-api-xxxxx   Running   ready=True   restarts=0
```

여기가 정상 상태입니다. 이 화면을 기억해두세요.

### B-2. 장애 목록 보기

```
python break_it.py
```

다섯 개가 나옵니다. `healthy` · `image-tag` · `oom` · `probe` · `both`

### B-3. 실제로 장애 내기  ★ 30~90초

```
python break_it.py oom
```

**일어나는 일**

1. 앱 매니페스트를 **Git 에 실제로 커밋** — 메모리 한도 128Mi → 32Mi
2. ArgoCD 에 즉시 갱신 요청
3. ArgoCD 가 클러스터에 적용 → 새 pod 생성
4. 앱이 기동 시 캐시 워밍업 48MB 를 잡으려다 **32Mi 한도를 넘어 OOMKilled**

화면에 상태 변화가 실시간으로 찍힙니다.

### B-4. 진짜로 죽은 것 확인

```
python status.py
```

**보이는 것**

```
Pods
  kdt-dev-api-xxxxx   Running   ready=False   restarts=3   CrashLoopBackOff
                                (직전 종료: OOMKilled exit=137)
최근 이벤트
!  BackOff   Pod/kdt-dev-api-xxxxx   Back-off restarting failed container
```

kubectl 이 있다면 같이 보면 좋습니다.

```
kubectl get po -n kdt-dev
kubectl describe po -n kdt-dev <파드이름>
```

### B-5. 에이전트가 진단  ★ 1~2분

```
python solution/agent.py
```

**일어나는 일**

| 턴 | 도구 | 무엇을 보는가 |
|---|---|---|
| 1 | `get_recent_changes` | 방금 무엇이 바뀌었나 — Git 커밋 |
| 2 | `get_application` | 지금 어떤 상태인가 — ArgoCD |
| 3 | `list_pods` | 어느 pod 가 문제인가 |
| 4 | `get_pod_logs` / `get_events` | 왜 실패하는가 |
| 5 | `send_report` | **승인 요청 → `y` 입력** |

`send_report` 는 쓰기 도구라 **사람이 승인해야** 실행됩니다.
리포트 내용을 읽어보고 `y` 를 누르세요.

마지막에 토큰 사용량이 찍힙니다. 그게 이 진단의 비용입니다.

### B-6. 메일 확인

승인했다면 등록한 주소로 진단 리포트가 옵니다.
받은 리포트를 **강의 채팅방에 공유**해 주세요. 서로 비교해봅니다.

### B-7. 복구

에이전트가 `rollback_last_change` 를 제안하면 승인하면 되고,
제안하지 않았다면 직접 되돌립니다.

```
python break_it.py healthy
python status.py
```

정상으로 돌아온 것을 확인합니다.

## C. 자동 감지 (여유 있을 때)

**터미널 두 개**가 필요합니다.

터미널 1 — 지켜보기

```
python watch.py --agent --solution
```

터미널 2 — 장애 발생

```
python break_it.py image-tag
```

15초마다 ArgoCD 상태를 확인하다가 `Degraded` 를 만나면
**사람이 아무것도 안 해도 에이전트가 알아서 실행됩니다.**

실무에서는 이 자리에 Alertmanager · ArgoCD Notifications · EventBridge 가 들어갑니다.
구조는 같습니다 — 신호가 오면 루프를 시작한다.

## D. 다른 시나리오도 해보기

```
python break_it.py image-tag     이미지 태그 오타 → ImagePullBackOff
python solution/agent.py

python break_it.py probe         readiness 경로 변경 → Ready 안 됨
python solution/agent.py

python break_it.py healthy       정상 복구
```

**`image-tag` 가 가장 흥미롭습니다.**
커밋 메시지는 `1.29.0 배포` 인데 실제 태그는 `1.290` 입니다.
Git 과 클러스터를 교차 확인해야 원인이 보입니다.

`probe` 는 가장 어렵습니다. pod 는 살아있고 앱 로그도 정상입니다.
이벤트를 봐야만 원인이 나옵니다.

## E. 클러스터 직접 보기 (선택)

kubectl 설치 없이:

```
python kube.py pods -A          전체 파드
python kube.py events           이벤트
python kube.py logs <pod> -p    직전 컨테이너 로그
python kube.py app              ArgoCD Application 상태
python kube.py svc              LoadBalancer 주소
```

ArgoCD UI 를 보고 싶다면:

```
python argocd_password.py
```

출력된 URL 과 비밀번호로 접속합니다. 자체 서명 인증서라 브라우저 경고가 뜹니다.

CloudShell 에서 kubectl 을 쓰려면 권한을 한 번 더 받아야 합니다.

```
CloudShell:  aws sts get-caller-identity --query Arn --output text
노트북:      python grant_access.py <그 ARN>
CloudShell:  aws eks update-kubeconfig --name kdt-devops-lab --region ap-northeast-2
             kubectl get po -A
```

## F. 정리  ★ 반드시

```
python cleanup.py
```

**EKS 클러스터는 켜두면 계속 요금이 나갑니다.**
방치하면 하루 약 $5 씩 쌓입니다. 해산 전에 꼭 실행하세요.

무엇이 지워지는지 먼저 보여주고 확인을 받습니다.
액세스 키는 `.env` 에 남으므로, 나중에 복습하고 싶으면
`python deploy_lab.py` 로 다시 만들 수 있습니다.
