## 0. 이 실습의 구조

강사용 서버가 따로 없습니다. **강사도 학생과 똑같은 폴더에서 똑같은 명령**을 씁니다.

```
[각자의 AWS 계정]  ×  참가자 수 + 강사
  EKS Auto Mode 클러스터
    ├─ ArgoCD
    ├─ Gitea (앱 매니페스트 저장소)
    └─ kdt-dev 네임스페이스 — 실제 nginx 앱
  SNS 토픽 (진단 리포트)
```

장애 주입도 각자 합니다. 강사가 화면에서 명령을 치면서 "다 같이 치세요" 하면
전원이 동시에 같은 상황에 들어갑니다.

## 1. 사전 준비

### D-7 — Bedrock 접근이 최우선

계정이 30개면 모델 접근 문제도 30배입니다. 여기서 막히면 강의를 미뤄야 합니다.

```bash
cd infra
python bedrock_preflight.py submit  --profile <조직관리계정>   # 1회, 멤버 계정에 상속
python bedrock_preflight.py verify  --profile <학생계정하나>
python bedrock_preflight.py profiles
```

Anthropic 모델만은 계정마다 최초 1회 사용 목적 양식이 필요합니다.
**AWS Organizations 관리 계정에서 한 번 제출하면 전체 멤버 계정에 상속**됩니다.
조직 관리 계정 접근 권한이 없다면 **지금** 클라우드 담당 부서에 요청하세요.

`profiles` 결과가 지금 기본값과 다르면 `student/.env.example` 의
`BEDROCK_MODEL_ID` 를 바꾸세요.

### D-7 — 계정별 실습 사용자

```bash
python create_student_user.py steve --profile <학생계정1> --out handout
```

출력된 네 줄을 학생에게 **1:1로** 전달합니다.

### D-7 — 본인 계정에서 전 과정 리허설

**네 시나리오 전부 돌려보세요.** 특히 `readiness` 는 난이도가 높아
Haiku 가 원인을 못 찾을 수 있습니다. 못 찾으면 실습에서 빼고 시연용으로만 쓰세요.

### D-3

## 2. 실습 진행

### Lab 0 — 환경 확인 (10분)

```bash
python check_env.py
python status.py
```

전날 배포를 안 한 사람이 있으면 지금 `python deploy_lab.py` 를 시키고,
25분 동안 A블록 이론을 진행하면 시간이 맞습니다.

### Lab 1 — 장애를 직접 일으켜본다 (15분)

```bash
python break_it.py                # 목록
python break_it.py image-tag      # 첫 시나리오
python status.py
python kube.py events
```

**여기서 반드시 짚을 것:** 커밋 메시지는 `1.29.0 배포` 인데 실제 태그는 `1.290` 입니다.
Git 과 클러스터를 교차 확인해야 원인이 보인다는 점이 이 시나리오의 전부입니다.

ArgoCD UI 를 띄워놓고 동기화가 실제로 일어나는 걸 같이 보면 좋습니다.

### Lab 2 — 에이전트 만들기 (25분)

`agent.py` 의 TODO 5개를 채웁니다. 순회하면서 **"시스템 프롬프트 쓰셨어요?"** 만
계속 물어보세요. 대부분 TODO 1 을 건너뛰고 루프부터 채웁니다.

### Lab 3 — 리포트 비교 (10분)

각자 받은 SNS 메일이나 터미널 출력을 강의 채팅방에 공유하게 합니다.
가장 짧은 것과 가장 좋은 것을 나란히 읽고,
**"이 두 분은 똑같은 도구 7개를 받았습니다"** 로 회수합니다.

### Lab 4 — 자동 감지와 복구 (15분)

```bash
# 터미널 1
python watch.py --agent
# 터미널 2
python break_it.py oom
```

에이전트가 알아서 깨어나 진단하고, `rollback_last_change` 승인을 요청합니다.
승인하면 **실제로 Git 커밋이 되돌아가고 ArgoCD 가 복구**합니다.

## 4. 트러블슈팅

`README.md` 의 표를 참고하세요. 실제로 겪은 문제들이 정리돼 있습니다.

강의 중 가장 빠른 진단 경로:

```bash
python status.py         # ArgoCD 동기화 실패 사유까지 표시됩니다
python kube.py events
python kube.py pods
```

### Windows 참가자

- `source .venv/bin/activate` 는 리눅스 명령입니다. PowerShell 은 `.venv\Scripts\Activate.ps1`
- 실행 정책 오류 → `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`
- **가상환경을 아예 건너뛰게 하는 편이 사고가 적습니다.** 패키지가 세 개뿐입니다.
  `python -m pip install -r requirements.txt`

**ArgoCD 가 `OutOfSync` 로 멈춰 있으면 동기화가 실패한 것입니다.**
ArgoCD 는 같은 리비전을 자동 재시도하지 않으므로 영원히 그 상태로 있습니다.
`status.py` 가 실패 사유를 출력합니다.
